## 钢琴页动态景深（DOF）修复

### 根因（持续朦胧模糊的四个叠加因素）
1. 远场 CoC 饱和：`clamp(|vz-focusDist|*uDof,0,1)*uDofMax`，地面盘半径 16m，下半屏全饱和 ~14 texel 模糊
2. 常驻边缘移轴 `def` + CA 色散与焦点无关，四周永远轻糊
3. 焦点拾取 120ms 节流 + 只在 raycast 命中钢琴时更新 → 鼠标离开模型焦点冻结、迟滞
4. 15 texel 模糊半径只摊 9 tap → 颗粒散景

### 用户决策（grill-me 访谈结论）
- 模糊强度参数维持现状（三套风格 dof/dofMax/edge 不动）
- 焦点机制：每帧轻量代理求交（钢琴包围球+键盘盒+地面平面），指哪清哪含地面
- 景深本质（用户原话）：鼠标所在距离的一个范围清楚，过近过远都模糊
- 兜底：运镜期焦点锁运镜注视点；鼠标离开画布/悬停 UI/未命中→钢琴中心 (0,0.9,-0.6)

### 代码改动
- `pianoGrade.ts`：新增 `uFocusRange`(0.25) uniform；CoC 改为 `clamp((|vz-f|-uFocusRange)*uDof,0,1)*uDofMax`——焦深带内完全清晰，带外原斜率渐糊，总量不变
- `PianoScene.tsx`：删 120ms 节流全模型 raycast；改每帧 `Ray.intersectSphere/Box/Plane` 代理求交（rootBox 上扩 0.95m 裕量防琴盖全开）；`PIANO_FOCUS_DEFAULT` 兜底；pointerleave 处理；运镜期跟焦 camTmp.target

## 钢琴页景深修复（会话完成）
- **真正的根因（两层）**：① `PianoPostProcessing` 的 EffectComposer 两个 render target 共享一张深度纹理,而 OutputPass/ShaderPass 依赖全局 `autoClear=true` → 绑定 rt1 时把共享深度清成 1.0；② MSAA(samples=4) 深度 resolve 在 SwiftShader/ANGLE-D3D 上静默失败 → 深度纹理恒为远平面 → Grade 的 CoC 恒饱和 → 整页恒定重模糊("一直朦胧"的真因)。
- **修复**：渲染期间 `gl.autoClear=false`(RenderPass 有显式 clear 不受影响) + `samples:0`(场景深度直写深度纹理)。诊断利器：shader 内临时输出 `d0` 灰度图 + 焦点扫描法(锐点在 60=vz 兜底值→深度空)。
- **焦点机制**：每帧代理求交(琴体 AABB+键盘盒+地面平面,clamp 盒顶 1.45m 防开盖峰值) → focusRef → 后处理 kf=14 阻尼驱动 uFocusDist；三段式：运镜期锁注视点/交互期跟鼠标/离开画布回钢琴中心(0,0.9,-0.6)。shader 加 uFocusRange=0.25 焦深清晰带。
- **代理求交的两个坑**：包围球在相机贴近时迎面切点比琴面凸 0.5m+(改用 AABB)；默认琴盖全开会把盒顶抬到 2.3m(钳制)。
- **验证设施**：`scripts/ab.mjs`(CDP 交互驱动,常驻 chrome --remote-debugging-port=9222,步骤间不断开) + `scripts/sharpness.py`(纯 stdlib PNG 解码+Laplacian 方差清晰度)。**坑：`vite preview` 后每次 `page.goto` 加新 query 拿到的是上一个构建(reload 才可靠)；uniform 属性拦截冻结法要兼容 value/accessor 描述符,否则 getter 崩掉 useFrame 假死(canvas 冻结导致对照实验全作废)。**
- 磁带页 post.js 同款配置存在相同隐患(AO 靠局部 autoClear=false 幸存,bloom/output 后深度仍会被清),待后续统一修复。
- tsc 仅剩 Film 页 5 个既有错误(与本次无关)；终版 console 零错误。

## 作品展示收藏柜：拖拽后 hover 变形失效（会话完成）

### 根因
- hover 变形(3D 倾斜+scale1.06)和粒子都由卡片 onMouseMove → `handleCardMove` 驱动(非 CSS :hover)，守卫：`if (hasDragged || ifMovable) return`。
- 拖拽生命周期：mousedown 复位 hasDragged=false → 移动>5px 置 true → **mouseup 只复位 ifMovable，hasDragged 残留 true 直到下次 mousedown**。
- hasDragged 不在 mouseup 复位的原因：`handleWorkCardClick` 靠它在 click 阶段拦截"拖拽后误跳 #trace"。副作用=拖拽一次后 hover 全失效，"再点一遍"(mousedown 复位)才恢复——与用户描述 100% 吻合。

### 修复（用户选"守卫瘦身"）
- `KiraFilmDemo.tsx` handleCardMove 守卫删掉 hasDragged 只留 `if (ifMovable) return`（一行）。拖拽进行中由 ifMovable 拦(本就不该变形)，hasDragged 保留本职(click 防误跳/cursor/dragging class)，互不干扰。无时序魔法。

### 验证（ab.mjs 交互式，全绿）
- 基线 hover：tilt 激活(scale1.06) ✓；拖拽>5px 卡片墙移动+无限回绕 ✓
- **拖拽后 hover：tilt 立即恢复(无需点击)** ✓；粒子同守卫恢复(3 颗生成) ✓
- 回归：拖拽往返后 click 落 trace 卡 → hash 保持 #film(防误跳仍有效) ✓；纯 click trace 卡 → 正常跳 #trace ✓

### 新增直达机制知识
- 收藏柜直达：`sessionStorage['kira-return']=JSON.stringify({section:1,detail:true})` → `/#film` → 1s 后 detailOpen。**设置标记后必须 reload() 而非 goto()**——SPA 内 goto 只是 hash 导航不重 mount，initialRestore(useMemo 同步读)不会重读。
- 上会话的 scripts/ab.mjs 与 sharpness.py 未留存(会话结束被清)；本次重建 ab.mjs，支持 goto/reload/eval/shot/mouse move|down|up/click/wheel/wait/waitfor 分步交互。ESM 不认 NODE_PATH，playwright-core 用 file:/// 绝对路径 import。

## 收藏柜→trace 跳转：整页透视飞入转场（会话完成）

### 需求（grill-me 两轮拍板）
- 旧转场="单纯的放大"：只有卡片克隆(缩略图+四角)贴图式盖屏，页面本身不参与。
- 用户要"以当前页面为结果的放大"→ 选 **3D 透视飞入**（非推荐的平面 scale，用户主动选了纵深感更强的）+ 保留白闪掩护。

### 实现
- `KiraFilmDemo.tsx`：zoomCard 状态简化为 {cx,cy,zt}；`zt = 1200×(1-1/zs)`，zs 沿用"卡片盖满视口"比例(max(vw/w,vh/h)×1.12)。**数学性质：zt 恒小于透视距离 1200（zs→∞ 时 zt→1200 渐近），投影永不翻转，无需 clamp**。卡片克隆层删除（真实页面本身就是放大主体）。
- `.work-detail-inner` 加 `zoom-through` class + 内联 transformOrigin(=被点卡片中心)+ `--zt`；CSS keyframes `perspective(1200px) translateZ(0)→var(--zt)`，0.6s 同曲线，700ms 切 hash 不变。
- 连带处理：粒子层转场期间 visibility:hidden（fixed 后代因祖先 transform 改变定位基准+粒子跟放无意义）；旧 .work-zoom-card/.work-zoom-corner CSS 全删。
- 坑：祖先加 transform 后内部 fixed 元素变相对定位——zoom overlay(白闪)跟 inner 一起变换但纯色层无视觉影响，可接受。
